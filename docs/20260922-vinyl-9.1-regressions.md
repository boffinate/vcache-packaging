# Vinyl Cache 9.1.0 VMOD regression triage

Source state: `ci-state/matrix` commit `3ce45d94eea6a97be7c06d605e45b069b8269542`, updated 2026-09-22 after matrix run 35714493400. The 9.1.0 conclusions below were produced by [matrix run 35581983126](https://github.com/boffinate/vcache-packaging/actions/runs/35581983126).

Thirteen VMOD rows are green on Vinyl Cache 9.0.1 and red on 9.1.0. Every regression repeats on all six targets: Debian 13 amd64/arm64, Ubuntu 26.04 amd64/arm64, and EL10 x86_64/aarch64. Eleven promoted rows fail in both compat and package mode, for 12 cells each. `curl` and `tus` are unpromoted and fail only their six compat cells. Eight rows have fixes through upstream source selection and the existing normalization mechanism. Five need upstream changes. No VMOD patches or test-suite changes are carried here.

## Selected upstream fixes (8)

- `cachetag`: compat fails at `make` and package mode at `pkg-build` because `vmod_cachetag.c` includes the removed `cache/cache_vinyld.h`. The Vinyl 9.1 selection is upstream release [`v1.0.2` at `d453872347e718a478e677aa551be2d4ae389916`](https://github.com/boffinate/libvmod-cachetag/commit/d453872347e718a478e677aa551be2d4ae389916), which accepts the renamed `cache/cache_int.h` while retaining the old spelling as a fallback.
- `cfg`: compat fails at `configure` and package mode at `pkg-build`; release `9.0-21.1` has an exclusive upper bound and reports `9.1.0 is not lower than maximum version 9.1`. The Vinyl 9.1 selection is upstream release [`9.1-22.0` at `e415e2f3b54691f56d38cfe16bf65b0ac9edab81`](https://github.com/carlosabalde/libvmod-cfg/commit/e415e2f3b54691f56d38cfe16bf65b0ac9edab81), which uses the 9.1 VCACHE build contract.
- `digest`: compat fails at `configure` and package mode at `pkg-build` with `Need varnish.m4`. After cross-family normalization the pinned source asks for the removed legacy `VINYL_VMOD_INCLUDES` macro, so the message names the macro file rather than the missing symbol. The selected source is upstream branch [`varnish-9.1.0-vcache-vmods` at `8c33b4a4ad9330acdb1fdb8577982ac5d028ecb8`](https://github.com/varnish/libvmod-digest/commit/8c33b4a4ad9330acdb1fdb8577982ac5d028ecb8), which migrates to `VCACHE_REQUIRE` and `VCACHE_VMODS`. Its single `varnish` provider uses the project’s generic cross-family provider translation for a Vinyl build. The initial package attempt also exposed a harness bug: artifact pruning kept `libvmod_digest.so` as a symlink but deleted its versioned target. The packaging fix materializes the declared shared object before pruning; it does not change upstream source.
- `geoip2`: compat reaches `make` but its bootstrap reruns configure and fails; package mode fails at `pkg-build`. The pinned source depends on the removed legacy VMOD macros, ending with `varnish.m4 is required` and `aclocal: couldn't open directory '/aclocal'`. The selected source is upstream devel [`d958af1dec630794af0695cf4181062a430e99e4`](https://github.com/varnishcache-friends/libvmod-geoip2/commit/d958af1dec630794af0695cf4181062a430e99e4), merged as PR 76, which declares both Vinyl and Varnish providers through `VCACHE_REQUIRE` and uses `VCACHE_VMODS`.
- `pesi`: compat fails at `make` and package mode at `pkg-build` because `misc.c` includes the removed `cache/cache_vinyld.h`. The selected source is upstream master [`916dd724a1854ba2988b0a040aa9c397fe6ea533`](https://code.uplex.de/uplex-varnish/libvdp-pesi/-/commit/916dd724a1854ba2988b0a040aa9c397fe6ea533), which changes all four private-header includes to `cache/cache_int.h`.
- `redis`: compat fails at `configure` and package mode at `pkg-build`; release `9.0-23.1` rejects 9.1 with the same exclusive upper-bound error as `cfg`. The Vinyl 9.1 selection is upstream release [`9.1-24.0` at `6d78352fb87d81604ace7099a042032601f9211e`](https://github.com/carlosabalde/libvmod-redis/commit/6d78352fb87d81604ace7099a042032601f9211e), which uses the 9.1 VCACHE build contract.
- `slash`: compat fails at `make` and package mode at `pkg-build`; the first error is `aux_cache_wrk.c` including the removed `cache/cache_vinyld.h`. Upstream master contains the header rename plus further Vinyl 9.1 changes for removed `synthetic()`, task scheduling, and broken ban exports. The selected source is [`567d30afa84bff9d11bea68c6360d580f80628f7`](https://code.uplex.de/uplex-varnish/slash/-/commit/567d30afa84bff9d11bea68c6360d580f80628f7), the current tip containing that series.
- `zipflow`: compat fails at `make` and package mode at `pkg-build` because `vmod_zipflow.c` includes the removed `cache/cache_vinyld.h`. The selected source is upstream master [`6191ac1949b32b6feaf2da4fc842bb5125c81f8e`](https://code.uplex.de/uplex-varnish/libvmod-zipflow/-/commit/6191ac1949b32b6feaf2da4fc842bb5125c81f8e), which changes the include to `cache/cache_int.h`.

## Remaining upstream work (5)

- `curl`: the VMOD builds and passes the load probe, then compat fails at `check`. Thirteen of fourteen upstream tests pass; `tests/test12.vtc` fails twice because its inline VCL calls the removed `synthetic(curl.body())`, and the VCC reports `Symbol not found: 'synthetic'`. Upstream master remains [`98da71c65568b1c1ca2868b7badf237e490ec524`](https://github.com/varnish/libvmod-curl/commit/98da71c65568b1c1ca2868b7badf237e490ec524) with that test unchanged.
- `gossip`: compat fails at `configure` and package mode at `pkg-build`; release `9.0-18.0` rejects 9.1 with the same exclusive upper-bound error as `cfg`. Upstream main [`e656f222c4d75d675e5378f9c3e964d5d52f5ed2`](https://github.com/carlosabalde/libvmod-gossip/commit/e656f222c4d75d675e5378f9c3e964d5d52f5ed2) removes the upper-bound call entirely, but Vinyl 9.1 needs `VINYL_PREREQ` or `VCACHE_REQUIRE` to initialise `VCACHEAPI_CFLAGS`; without it, configure cannot find the installed `vsha256.h`. The upstream source needs a real prerequisite declaration rather than a version-guard bypass.
- `jq`: compat reaches `make` but bootstrap reruns configure and fails; package mode fails at `pkg-build`. Like `geoip2`, the source relies on removed legacy VMOD macros and reports `varnish.m4 is required` followed by the invalid `/aclocal` path. Upstream devel is still [`4051a7d08dc3a4ca90d9e8319d5a3a132793e1da`](https://github.com/varnishcache-friends/libvmod-jq/commit/4051a7d08dc3a4ca90d9e8319d5a3a132793e1da) from 2022; no VCACHE migration exists there.
- `querystring`: compat fails at `make` and package mode at `pkg-build`. Vinyl 9.1 makes `WS_Reservation` a function-like macro. The configure probe tests it as a bare symbol and incorrectly selects the fallback to the removed `WS_Front`, causing an implicit-function declaration and pointer-from-integer assignments. Upstream master has moved only to [`a3dabb8b2a82577badd4cc4409a4fac9d2bd74af`](https://git.sr.ht/~dridi/vmod-querystring/commit/a3dabb8b2a82577badd4cc4409a4fac9d2bd74af), with no 9.1 API adaptation found.
- `tus`: compat fails at `make` because generated `vmod_get_h.c` dereferences `const struct vmod_data`, whose definition moved to `vmod_abi.h` in Vinyl 9.1; the helper does not include that header and the compiler reports three `invalid use of undefined type` errors. Upstream master remains [`7dd1a25a8a792df72cdbef1ac58db8e838b44c4e`](https://code.uplex.de/uplex-varnish/libvmod-tus/-/commit/7dd1a25a8a792df72cdbef1ac58db8e838b44c4e), with no adaptation found.

## Scope constraints

The repository may select newer upstream refs per engine series and may apply the documented generic source-family spelling normalization in disposable checkouts. It may not carry VMOD patches, ported upstream tests, or vendored sources. A regression without a suitable upstream ref therefore remains an honest red cell unless the project points the catalog at a fork. Red compatibility cells do not fail matrix jobs, but a promoted VMOD that remains red prevents publication of that engine and target pair under the release completeness gate.

## Validation and release identity

The catalog uses `sources.by_series.vinyl-9.1` overrides for these eight VMODs. The default sources used by Vinyl 9.0.1 and Varnish releases remain unchanged. Vinyl 9.1.0 package revision increases from 1 to 2 because the selected VMOD source bytes change. The revision-2 engine builds successfully in the project Docker harness.

All eight selected sources pass compatibility build/load and package build/install/load checks on native `debian-13-arm64`: 16 passing VMOD cells. Package checks install the revision-2 engine and each VMOD in a fresh container before loading it. Cachetag also passes all 53 declared upstream tests. The other seven retain their existing build/load verification contract; no test declaration is removed. The host-safe tooling suite passes 96/96 tests, including provider translation and package symlink handling. Other operating systems and architectures await CI.
